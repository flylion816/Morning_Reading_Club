# 声纹与生产核验

## 开始制作前

确认脚本版本和改写授权；保存来源清单及哈希。探测 Python/Node、字体、TTS 模型实际加载能力、HyperFrames、FFmpeg/ffprobe 可用性。针对选用的字幕方案运行短段测试：FFmpeg `-filters` 检查 ass/subtitles/drawtext 支持；缺失时优先找已有兼容二进制，或实际渲染字幕图层，不默认安装系统组件。检查编码器后试编码；参数支持不能替代成片解码验证。

## 每个角色的声音

1. 确认参考音频与角色对应、单一说话人、无明显背景干扰；记录哈希、采样率、时长和参考转写。
2. 根据用户指定及环境选择引擎；本机可用 VoxCPM2 仅作为选项，不能硬绑定历史绝对路径。先生成真实试听，验证模型已就绪。
3. 多角色试听包括普通句、带姓名句；如有诗歌/建议/尾声，测对应语气。需要同人不同风格时复用声纹而非另换声音。
4. ASR 检查遗漏、增词、重复、人名和外语；多音字保留正文，单独留合成提示。疑似同音误识别需听辨或复核，不能直接降低阈值。声纹相似度只作辅助，配合人耳试听。
5. 单段最长长度依模型能力确定，长段按原标点切分，不截断；按实测音频重建时间轴。

## 镜头与混音

先验证代表性镜头尺寸、文字溢出、图片完整、姓名对应和字幕安全区，再批量渲染。只有所有动画确实结束的镜头才能“渲染入场后保持末帧”；有后续运动时完整渲染。用户希望电影运动感时不能用静帧方案冒充。

音频统一采样率和声道，以旁白清楚为中心做音乐避让、淡入淡出，检查峰值、失真和段落接缝。字幕来自批准台词，参考 ASR 时间戳；对错词先修音频，不能仅改字幕掩盖。版权/署名信息随成片交付。

## 成片测试

- 台词覆盖按 `verbatim` 原文或 `adaptation` 批准稿核验，保留原始来源；改写稿检查与原文差异有说明，不把原文改成脚本以制造通过。
- 镜头数、人物数、章节数由当前 manifest 推导；末镜/新增尾声进入真正的时间轴、字幕、音轨与元数据。
- FFprobe 确认分辨率、帧率、编码、音轨和时长一致。全片解码；检测异常连续黑帧并人工区分剧情需要。
- 从实际最终 MP4 取样：每位人物、每种关键布局、建议、尾声及切换边界；看文字、照片和字幕。播放样片及所有补配段，说明尚未完成的人耳全片审阅。
- 前序流程失败不能标 ready；原文核验、音频核验、视觉核验和导出核验分别记状态。
- 最终文件新命名，保留旧版；不要覆盖来源、声纹原文件或用户旧成片。

报告真实耗时和剩余阶段，不捏造“几分钟全部完成”。只修改局部时可复用通过核验的其他段，说明复用比例；用户要求从零重做时创建新工程并列出仍需复用的原始素材。
