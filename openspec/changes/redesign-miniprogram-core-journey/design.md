## Context

小程序使用原生 WXML/WXSS。全局已有 `--app-*` 基础令牌和租户生成的 `--theme-*` 主色体系。核心页面存在较多页面级重复样式，直接重写结构会带来高回归风险。

## Goals / Non-Goals

- Goals: 建立可复用的视觉基础；让主链路在排版、色彩、卡片、按钮、表单和反馈上保持一致；保留现有功能。
- Non-Goals: 不迁移框架；不引入字体文件；不重写业务逻辑；不在本阶段覆盖所有分包页面。

## Decisions

- 采用 CSS 变量和公共样式类作为轻量设计系统，避免新增运行时依赖。
- 版本一优先做样式和少量结构优化，不改变数据流。
- 按压反馈优先使用 `:active` 和统一 `hover-class`，复杂动画只用于页面轻量进入效果。
- 表单、支付和阅读页保留业务组件，通过统一类名接入设计系统。

## Risks / Trade-offs

- 页面级 WXSS 较长，一次性清理会增加风险；版本一只收敛新增和关键区域样式。
- 微信客户端样式表现存在差异，需要通过主题扫描、Jest 和小程序编译回归降低风险。
