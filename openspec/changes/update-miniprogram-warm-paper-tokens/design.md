## Context

小程序使用原生 WXML/WXSS，全局已有 `--app-*` 基础令牌和租户脚本生成的 `--theme-*` 主色体系。页面样式里引用令牌的地方很多，所以改令牌能带动全局变色，但也残留了写死的绿调 `rgba(49,72,56,…)` 与冷灰色值，需要一次清扫。`apply-tenant.js` 在切租户时会把页面级导航色统一改回租户色，目前只豁免自定义导航和「在场」。「在场」自带一套深绿加米色的子品牌，与新的全局暖纸几乎同色又不完全一致。

## Goals / Non-Goals

- Goals:
  - 让中性色整体变暖，文字与辅助文字在纸色底上对比度不低于 4.5:1。
  - 建立晨光辅色，使三个租户（蓝、绿、橙红主色）都成立。
  - 导航栏规则清晰可测试：默认纸色，品牌页例外，例外名单可维护。
  - 用印章与内联 SVG 线性图标替换 emoji，各机型一致。
  - 核心链路文案统一口吻。
- Non-Goals:
  - 不改租户主色、logo、Tab 图标图片。
  - 不换框架、不引入组件库、不新增字体文件。
  - 不做全局深色模式。
  - 不重写业务逻辑，不动首页结构（留给第二批）。
  - 移动管理页只跟随令牌变色，不专门设计。

## Decisions

- Decision: 品牌主色管「做什么」（按钮、选中、链接），晨光色只管「此刻」（时间、进度、庆祝）。两者不混用。
  - Alternatives considered: 用主色承担全部强调——三租户下无法形成统一的暖感，仪式时刻没有记忆点。
- Decision: 晨光色 `--app-dawn` 只用于图形，文字用 `--app-dawn-ink`，避免橙色小字对比度不足。
- Decision: 改令牌与改测试断言放在同一次提交，`brand-color-regression.spec.js` 改写成新规则的断言，而不是删掉。
- Decision: 导航栏维护一份「纸色导航页」与「品牌导航页」名单，`apply-tenant.js` 读取名单，只对品牌页写回租户色，并补脚本测试。
- Decision: 「在场」使用作用域主题覆盖，即在「在场」页面根节点把 `--theme-primary` 系列覆盖为深绿 `#2D5A3D`，按钮、筛选、印章、链接自动跟随；中性色全部走全局令牌，赭石并入晨光色系。
  - Alternatives considered: 继续保留「在场」独立的一整套色值——会与全局暖纸并排出现两种略有差别的米色。
- Decision: 衬线字体按「黑体回退也成立」来排版。数字衬线在 iOS 与安卓都生效，中文衬线标题 iOS 生效，安卓自动回退黑体。
- Decision: 线性图标用内联 SVG 遮罩实现（沿用 `pages/index/index.wxss` 的 `book-icon-svg` 做法），颜色跟随文字色与主题色；图标总量控制在 20KB 内，不新增图片资源。
- Decision: 触感只在四个时刻触发（点赞、打卡成功、读完、长按摘句），统一经 `utils/feedback.js`，页面不直接调用 `wx.vibrateShort`。
- Decision: 不全量重写 245 处 `wx.showToast`，只把核心链路约 20 处成功提示换成统一轻提示，错误提示保持系统样式。

## Risks / Trade-offs

- 设计回归测试会因色值变化失败 → 令牌与断言同一提交修改，改写而非删除。
- 切租户脚本把纸色导航覆盖回租户色 → 同步修改 `apply-tenant.js` 并补脚本测试。
- 暖色底上三个租户主色观感不同 → 三租户各切一次，首页、课程详情、打卡三页截图对比后再发。
- 衬线体在安卓与鸿蒙上回退 → 按黑体也成立排版，真机确认后再决定是否扩大使用范围。
- 内联 SVG 遮罩依赖 WebView 渲染 → 当前未启用 Skyline；若以后切换需重新评估。
- 硬编码清扫可能漏掉低频页面 → 以主题色扫描脚本加静态测试兜底，并保留清扫清单。

## Migration Plan

1. 先改令牌与测试，再清扫硬编码，最后改导航、图标、文案。
2. 每一步独立可回滚；令牌回滚只需改回数值。
3. 本批可独立发布，无数据迁移。

## Open Questions

- 衬线字体在鸿蒙与部分安卓机型上的实际效果，需要真机确认后再定使用范围。
- 方案文档未给出「纸色导航页」与「品牌导航页」的完整页面清单，实施时需先列清单并在评审中确认。
