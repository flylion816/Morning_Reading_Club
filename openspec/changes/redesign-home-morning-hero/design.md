## Context

首页根节点目前是个人名片结构，今日任务有 5 种以上分支（未登录、未报名、进行中、已完成、期次间隙等）。打卡成功有 7 套庆祝样式（A 至 G），后台可按租户配置启用哪些。登录页是整屏主色加悬浮白卡，三个租户的 logo 只有 81×81 像素，凡人共读与另一租户还共用同一个灰色占位图标。首页板块的顺序与显隐由后台首页配置决定。

## Goals / Non-Goals

- Goals:
  - 首屏回答三件事：现在是清晨吗、今天第几天、今天读什么，并只给一个主行动。
  - 打卡与读完像同一个仪式的两步。
  - 登录页保住品牌主色的第一印象，同时与晨光整体统一。
  - 等待与空态有品牌感。
- Non-Goals:
  - 不做全局深色模式，夜间只让问候区变深。
  - 不改后端接口、数据模型与庆祝配置结构。
  - 不改首页板块的后台排序与显隐机制。
  - 不重做登录流程，不替换租户 logo。
  - 不在本批展示「我的」手账（第三批）。

## Decisions

- Decision: 品牌主色管操作，晨光色只管时间与仪式。主按钮用租户主色，太阳、进度、光晕用晨光色。
- Decision: 时段分四档：破晓 5–8 点、白天、黄昏、夜晚；时段由本地时间计算，无需接口。
- Decision: 首页导航底色用 `wx.setNavigationBarColor` 随时段设置，不改为自定义导航，以降低风险。
- Decision: 先列全首页状态清单（未登录、未报名、进行中、已完成、期次间隙等）并为每个状态留截图，再动手改结构。
- Decision: 主按钮按状态切换：开始晨读、去打卡、今日已完成；今日一句取课程「摘一摘」内容，没有则不显示该行。
- Decision: 庆祝样式仍叫 C，仅升级视觉；这样后台配置、存量数据与接口全部兼容，不需要迁移。
  - Alternatives considered: 新增样式 H——需要改后台配置与后端枚举，超出本批边界。
- Decision: 「你是今天第 N 位打卡的书友」若现有数据无法提供名次，则隐去该行而不新增接口。
- Decision: 动效三档时长：按压 120ms、状态切换 220ms、进入 360ms，仪式类约 1 秒；检测到系统减少动态效果时，用淡入替代位移与弹跳。
- Decision: 空态插画用内联 SVG，每张不到 2KB；骨架屏复用 `app.wxss` 中已有 `.app-skeleton`。
- Decision: 登录渐变路径为主色、主色浅调、暖白，再叠晨光光晕，不直接从蓝过渡到橙，避免中间发灰。
- Decision: 登录页「稍后登录」保持清晰可见的按钮形态（审核要求）。
- Decision: 登录页徽记为白色线描徽记（摊开的书页上升起太阳），以后有高清 logo 再替换。

## Risks / Trade-offs

- 首页状态多、分支易遗漏 → 实施前列全状态清单，每个状态留截图，并补对应 Jest 用例。
- 夜晚问候区文字反白后可读性 → 清晨、白天、夜晚三个时段各截图确认。
- 动效在低端机卡顿 → 仪式动画只用 transform 与 opacity，并支持减少动态效果。
- 破晓渐变在三个租户主色上观感不同 → 三租户各切一次截图对比。
- 名次数据缺失 → 允许隐藏该行，不为此新增接口。

## Migration Plan

1. 先改首页结构与状态分支，保持板块配置读取逻辑不变。
2. 再升级样式 C 与读完提示，最后改登录页。
3. 每一部分独立可回滚；无数据迁移。

## Open Questions

- 方案未说明「已打卡书友头像」取多少个、数据来自哪个现有接口，实施时需核对。
- 夜晚时段（几点到几点）与黄昏的具体边界，方案只给出了破晓 5–8 点，其余需在实施时确认。
