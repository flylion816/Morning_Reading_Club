## Context

- 「送一句」在 `backend/src/services/buddy.service.js` 的 `gift()` 里实现：校验 key → 原子占当天名额（`BuddyPair.gifts` 的 `$push`，带 `$not $elemMatch` 保证每人每天一条）→ 控制器发 `buddy_gift` 站内通知（内容 `昵称：「句子」`）。
- 句子只存 key，状态、同行时间线、结营纪念都用 `GIFT_MESSAGES[key]` 取文本。
- 项目里还没有任何内容安全调用；`wxacode.service.js` 已经示范了「用租户 access_token 调微信接口」的写法。

## Decisions

### 1. 内容安全：服务端、保存之前、只放行 pass

- 新服务 `content-security.service.js` 导出 `checkText({ openid, content })`：通过时正常返回；没通过抛 `CONTENT_RISKY`；出错或超时抛 `CONTENT_CHECK_UNAVAILABLE`。控制器据此返回 400 或 503。
- 调用微信 `POST https://api.weixin.qq.com/wxa/msg_sec_check?access_token=…`，请求体用 2.0 版：`{ version: 2, openid, scene, content }`，`scene` 取「评论」。access_token 用现有的 `subscribe-message.service.getAccessToken()`（和 `wxacode.service.js` 一样按租户取）。
- 只有 `errcode === 0` 且 `result.suggest === 'pass'` 才放行；`risky` 和 `review` 都按没通过。其余 errcode、网络错误、超时（5 秒）都按服务不可用。
- 2.0 需要发送者的 openid（`User.openid`），官方还要求该用户近期访问过小程序（发送时人就在小程序里，自然满足）。**以上参数和限制凭记忆写成，这次没能联网核对，实现的第一步要对照微信官方文档逐项确认，不一致就以官方为准。**
- 顺序：规范化与长度、链接、联系方式校验 → 内容安全 → 原子占名额 → 保存 → 通知。检查没通过就不占名额，用户可以改一句再送。
- 日志不记原文，只记 trace_id 和结论。

### 2. 链接和联系方式：简单规则，不追求拦住所有变体

拒绝 `http(s)://`、`www.`、常见域名后缀、邮箱、连续 6 位以上数字，以及「微信 / vx / 加我」后面跟字母数字串。这只是防广告引流的一道粗筛，真正的把关是内容安全检查。

### 3. 预设短句轮换放在服务端

- `GIFT_MESSAGES` 从 4 句扩到 20 句，key 是 `here`、`here2` … `here5`，其余三类同理（`reread`、`noRush`、`tomorrow`）；原来的 4 个 key 就是各类的第一种说法。
- 每天每类选哪种说法：`(东八区日序号 + 用户 id 末位) mod 5`。同一个人连续两天一定不同，不同的人同一天也会不同。
- 状态里返回 `giftOptions: [{ key, text }]`（今天这位用户看到的四句）。小程序直接渲染，没有这个字段时退回原来的 4 句。服务端仍然接受 20 句里的任何一个 key，不限定当天那四句。

预设短句的文案（每类第一句是原有的）：

| 类别 | 说法 |
| --- | --- |
| 在一起 `here` | 今天有你一起读，真好。／知道你也在读，我就安心了。／我们又读到同一天了。／这一页，有你陪着读。／一个人读也好，有你在更好。 |
| 读到你写的 `reread` | 你写的那段，我读了两遍。／你写下的那句，我记住了。／读你写的字，我慢了下来。／你的那段话，我也有同感。／谢谢你把心里话写出来。 |
| 不用赶 `noRush` | 不用赶，我在这儿。／今天读不完也没关系。／慢慢读，我陪着你。／累了就歇一歇，明天再读。／你读多少，都算数。 |
| 明天见 `tomorrow` | 明天还在老地方见。／明早，我先到。／明天一起，接着读。／今天到这儿，明天见。／睡个好觉，明早见。 |

### 4. 数据

`BuddyPair.gifts[]` 加可选 `text`（maxlength 60，留余量）；自己写的话 `key: 'custom'`。读取端统一走 `giftText(gift)`：`custom` 取 `text`，否则查预设表；表里没有的旧 key 返回空串（沿用现在的容错）。状态、时间线、结营纪念、通知都用它，不再各自查表。

### 5. 小程序弹层

- 预设短句下面加一块「自己写一句」：多行输入框 + 字数 `n/30`。点输入框时取消预设选中，选预设时收起键盘；「送出」按输入框里有没有内容决定发 `text` 还是 `messageKey`。
- 键盘：沿用速记条已经在真机上跑通的做法（输入框 `adjust-position` 关掉，监听键盘高度，弹层 `bottom` 跟着走）；屏幕放不下时预设区域可以滚动。
- 服务端的提示（400 / 503 的 message）原样显示。

### 6. 限频和提示

- 路由 `POST /buddies/period/:periodId/gift` 加限频：每人每分钟最多 10 次（失败的尝试也算），避免重复提交耗掉内容安全接口的额度。
- 小程序的请求层会把 5xx 统一成「服务器开小差了」，所以 503 的提示由页面自己换成「暂时没法送自己写的话，先选一句预设的吧」；400 的原因（没通过、字数、链接）原样显示。
- 自己写的话被拒时，弹层和已经写的内容留着，不用重写。
- 弹层里有一行小字「自己写的话会先过一道内容检查」，让人知道为什么有时送不出去。

## Risks / Trade-offs

- 内容安全接口按 appid 有调用频率限制，具体数字实现时查官方文档；每人每天最多一次，量很小。
- 检查服务不可用时拒绝自己写的话，会让一部分人暂时只能选预设短句；这是有意的取舍。
- 轮换放在服务端意味着改文案要发后端，不用发小程序。
