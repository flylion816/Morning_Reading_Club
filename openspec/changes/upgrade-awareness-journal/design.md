## Context
随喜记（`add-joy-notes`）已上线：私有、可选关联期次和课程、列表与搜索。本次要把它扩成两种写法，并增加一周后的回访。约束：多租户隔离、笔记仅本人可见、小程序主包体积（分包规则：主包不能引用分包文件，且主包中不应出现没人使用的文件）、不接入 AI。

## Goals / Non-Goals
- Goals：随喜在原页面 3 步写完；觉察是一条慢的、能叩问的路径；一周后有回声；已有数据零迁移；笔记文字不进入通知数据。
- Non-Goals：公开分享、点赞评论、AI 提问、统计报表。

## Decisions
- **同一个集合，加 `kind` 区分**：`JoyNote.kind` 取 `joy`（默认）或 `awareness`。理由：列表、分页、搜索、期次筛选、所有权校验都已经建立在这个集合上；缺 `kind` 的历史记录按 `joy` 处理，查询随喜用 `kind != awareness`。备选：单独的 `AwarenessEntry` 集合——会让「全部」列表需要合并两个分页来源，被否决。
- **`content` 保持必填，由结构化字段拼出**：觉察记录的 `content` 由服务端按「看 / 感 / 问 / 择」拼成纯文本（最长 3000 字），以便沿用关键词搜索、复制、日签等现有能力；结构化内容放在 `awareness` 子文档：`facts`、`feelings[]`、`bodyAreas[]`、`feelingNote`、`asks[{level,question,answer}]`、`habitKey`、`choice`、`followUps[{content,createdAt}]`、`revisit{enabled,status,dueAt,deliveredAt}`。各字段长度上限合计小于 3000，保证拼接不会超长。
- **草稿只放本机**：觉察静室的草稿和速记条的草稿都存在 `wx` 本地存储（按租户与用户区分），不写服务端。理由：半成品不应该进入服务端，也不增加接口。代价：换设备不会同步草稿，在页面文案里说明。
- **题库放在小程序里**：八组问题是静态内容，放在主包 `utils/awareness-questions.js`（首页营地角落也要用来换每天的门上问题）。每条回答保存 `question` 原文，所以以后改题库不影响历史记录。习惯识别按课程标题关键词（「第 N 个习惯」、七个习惯名称）匹配，匹配不上用通用组。
- **心情分沉与亮，问题跟着心情走**：原来的十四个情绪词里有十一个是难受的，开心的事很难走进来。改成「沉一点的」「亮一点的」两组各八个。每组习惯在原来两条问题链（`ladders`）之外，加一条「种子」问题链（`seeds`），通用组两条：顺着这份好心情，问它从哪一刻开始、碰到了我在意的什么、那是心里的哪一颗种子。进入「问」时按已选的词出题：只选亮的，先给种子（本习惯一条，再是通用两条）；只选沉的，给原来的两条；两种都有或没选，先给沉的，「换一问」能换到种子；已经写了回答就不再换题。问题里的 `{feeling}` 换成选的词（没有词时用「情绪」「好心情」）。「择」的问题、输入提示和收尾那句话跟着问题链换。草稿记下出题时的心情，恢复后问题和回答对得上；旧草稿没有这一项，按没选心情出题。门上的话和「看」的例子也补上明亮的一面。服务端本来就不限定情绪词，接口不用改。
- **自己加的情绪词只放本机，按组记**：内置的词不一定够用（比如「担心」「害怕」），所以「感」里有一行「找不到合适的词？自己加一个」：写一个词（最多 8 个字，与服务端单个词的上限一致），选加在「沉一点的」还是「亮一点的」，点「加上」后它出现在那一组的末尾并被选中。**加在哪一组，就按哪一组算明暗**（`ladderContext(feelings, custom)`），所以问题照样跟着心情走，不需要判断词的意思。词表存在本机（`awarenessCustomFeelings:<用户>`，`{ heavy: [], bright: [] }`），每组最多 8 个，长按虚线框的词可以删掉，内置的词不能删；词表里已有的词（不论在哪一组）不重复加，只帮忙选上。草稿里同时记下词表，恢复时和本机的词表合并，所以词表里删掉了的词，草稿里选着的也不会丢；认不出在哪一组的词（比如旧版本里的词）不带回草稿。服务端本来就不限定情绪词，接口不用改，也不需要迁移；换设备不会同步词表，与草稿一样。
- **回访用独立定时任务**：`awareness-revisit.service` 与慢递邮局投递同样的运行方式——生产环境默认启用、仅在 PM2 实例 0 运行、每 10 分钟扫描、`withSystemContext` 逐条切换到记录所属租户。到期时间在创建时算好：创建当天起第 7 天的东八区 06:00。
- **投递幂等**：先把 `awareness.revisit.status` 从 `pending` 条件更新为 `delivering`（只有一个执行者能成功），再创建通知；通知创建成功后置为 `delivered`；通知失败则退回 `pending` 下一轮重试。通知按 `data.joyNoteId` 做幂等 upsert，避免重复。
- **通知不含笔记文字**：通知的标题与内容是固定文案，`data` 只带 `joyNoteId`。来信页拿到列表后，用 `GET /joy-notes/revisits?ids=` 一次读取最多 10 张回访卡片（择的文字、日期、状态、后来数量）。理由：通知会被同步到其他存储，私人文字不应随之扩散。
- **「发成今天的打卡」走打卡草稿**：把觉察内容写入打卡页已有的本地草稿再跳转，复用现成的草稿恢复逻辑，可见范围到打卡页再选；不新增服务端接口。
- **共用代码位置**：首页（主包）和阅读页（分包）都要弹速记条，所以速记条做成主包组件 `components/quick-note`，其服务 `services/joy-note.service.js` 也放主包（分包可以引用主包，反之不行）。

- **标题**：`JoyNote.title`（选填，最长 40 字）。觉察记录创建后唯一允许修改的就是标题（`PUT` 只接受 `title`），随喜仍可整体编辑。列表搜索同时匹配标题和正文。
- **富文本双份存储**：随喜存 `contentHtml`，觉察的「看」「问」「择」存 `factsHtml`、`asks[].answerHtml`、`choiceHtml`。HTML 一律经共用的 `utils/rich-text.js` 白名单清洗（与打卡同一份规则：标签、样式属性、长度），**纯文本由服务端从清洗后的 HTML 推出**，客户端传来的纯文本不被信任，所以 `content`、搜索、复制、日签、回访来信不会和 HTML 不一致。没有格式时只存纯文本，不存 HTML。
- **输入框组件**：`components/rich-input`。**默认是普通输入框**（键盘立刻弹起，速记不变慢），点右下角「Aa」才升级成微信 `editor` + 工具栏（B I U、标题、列表、五种颜色、撤销重做，与打卡页一致）；内容本来就带格式时直接用编辑器打开，保存后下一条重新从普通输入框开始。对外只有 `value` / `html` 属性与 `input` 事件（detail 为 `{ text, html }`，没有格式时 `html` 为空）。放在主包：速记条（主包组件）要用，分包页面也能用。夜色的静室里，编辑器放在一张纸色卡片里，保证文字和颜色在深色背景上依然清楚，也让选的颜色在之后的浅色页面里还是清楚的。
- **展示与长图**：详情、列表、分享页用 `rich-text` 展示清洗后的 HTML；长图把 HTML 解析成带样式的文字片段（颜色、粗体、下划线、标题、列表）再在 canvas 上逐行排版，不走 `rich-text`。
- **分享码**：`JoyNoteShare`（每条笔记至多一条，`code` 8 位、租户内唯一）。「停止分享」只标记 `revokedAt`；之后再分享会**换一个新码**，旧链接和旧二维码永远失效。删除笔记同时删除分享。
- **谁能看**：`audience` 为 `period`（默认，仅当笔记关联了期次）时，非作者必须有该期次的社群权限；为 `login` 时任何已登录的同租户书友都能看。作者始终能看。无论哪种，未登录、分享已撤销、笔记已删除、作者已停用都按「打不开」处理，小程序一律跳回首页。`audience: login` 的访客看不到期次名和课程名。
- **分享视图只读且不可再转发**：分享落地页隐藏转发菜单，页面里没有转发入口。
- **小程序码**：复用阅读分享的做法，`scene` 只放 `s=<码>`，`getwxacodeunlimit` 带上当前环境版本，缓存 6 小时；生成失败时长图退回通用小程序码（扫码到首页）。
- **只在真正分享时才开启**：打开分享面板会先创建或取回分享；如果这次是新建的、而用户关闭面板时既没转发也没生成长图，就自动撤销。已经开启过的分享不受影响。

## Risks / Trade-offs
- 觉察静室是新的长流程，若入口太显眼会挤占随喜 → 页面上输入框在前、门在后，随喜路径一步不增加。
- 定时任务与慢递邮局共用启动条件 → 沿用 `ENABLE_LETTER_DELIVERY` 之外，新增独立开关 `ENABLE_AWARENESS_REVISIT`，生产环境默认启用，便于单独关闭。
- 回访来信到期时用户已删除记录 → 投递前读取记录，不存在或已被跳过则不发送。
- 旧版小程序不认识 `awareness_revisit` → 来信页对未知类型本来就按通用来信展示，不会报错，点开无动作。

- 富文本在不同设备上的表现不一 → 工具栏、格式状态沿用打卡页已经跑通的逻辑；编辑器初始化失败时降级为只读提示，不丢文字。
- 觉察的私人内容被分享 → 分享是逐条、主动、可撤回的；面板明确提示；落地页不可再转发；长图只是图片，由用户自己决定发给谁。
- 同一条笔记旧链接泄露 → 停止分享后再分享会换新码。

## Migration Plan
无迁移。新增字段均有默认值；`kind` 缺失视为 `joy`。回滚：关闭 `ENABLE_AWARENESS_REVISIT`，已写入的觉察记录仍可作为普通记录读取（`content` 是完整文本）。
