# 课程模板设计

## 目标与边界

管理员维护可复用的课程模板；新建期次时绑定一个模板；每期所有课节共享同一套模块结构，不同课节填写不同内容。支持模板手机预览，允许旧七个习惯课程照常使用。第一版不提供自由拖拽排版、多正文模块、每课独立结构或跨租户共享自建模板。

## 管理操作

1. 管理后台在期次管理附近增加“课程模板”，展示模板名称、模块概要及状态；支持新建、编辑、复制、停用和预览。
2. 编辑器填写模板名称，添加模块并设置名称、类型、顺序；支持上移、下移、删除。类型为短文本、多行文本、正文、图片。正文最多一个；允许无正文，但此时不展示正文特有功能。短文本和多行文本的长度限制需统一前后端，并在界面标明。模板同时配置“时长（分钟）”“结营视频”“凡人播客”三个扩展能力开关，控制新增课节表单中对应的扩展区域；旧模板缺少配置时默认全部启用。
3. 编辑器提供“手机预览”，使用手机比例容器展示示例课节标题、模块名、顺序和示例内容，文字、正文和图片使用各自的近似渲染方式。增删、改名、排序、切换类型即时反映；预览明确标识为模拟效果，不创建课节、不发布内容。可打开已保存模板预览，也可预览未保存草稿；移动窄屏应可操作。
4. 新建期次时必选模板，旁边提供“新建模板”；完成创建后返回原表单、保留已填内容并选中新模板。停用模板不供新绑定。对历史默认行为和旧管理客户端采用受控兼容策略。
5. 选定期次后的“新增课节”依据快照渲染字段和顺序，正文沿用 Markdown / 富文本编辑，图片沿用安全上传。选填模块无内容时学员端隐藏。

## 数据和生命周期

- 新增租户隔离的模板实体：模板 ID、租户 ID、名称、状态、版本及模块数组。模块包含稳定 ID、名称、类型和顺序；名称不是数据键。预置七个习惯模板作为内置默认定义提供给每个租户，无需执行数据库初始化；租户复制后编辑自己的模板，不允许修改全局默认定义。
- 期次保存模板来源 ID、版本和完整模块快照。模板修改只影响之后绑定的期次。复制期次复制源期次快照及课节数据，不追随模板最新版本。
- 课节以模块稳定 ID 保存值；根据类型校验并设置统一的容量限制。新期次快照是读取和展示结构的权威来源，不依赖模板后续存在。旧课节保持原有字段结构。
- 同期结构固定：第一版期次已有课节后禁止更换模板或修改快照；无课节时允许管理员更换，界面和服务端都校验。通过克隆模板并创建新期次处理结构变化；不实现直接修改已有期次结构。
- 删除模板模块只影响模板未来版本；已绑定期次快照不变。已绑定模板可停用而不可物理删除；未绑定模板第一版亦采用停用，避免误删。保存编辑时使用版本校验以防覆盖其他管理员的更改。
- 历史期次无快照时，通过内置七个习惯定义和旧字段映射适配读取；不依赖批量迁移。历史课程更新不得丢失旧字段；旧期次复制继续保持七个习惯语义。

## 展示与功能契约

- 后端为新客户端返回期次模块快照及课节对应值；课程详情、打卡页按模块顺序显示非空值。打卡页收起状态选第一个非空模块作为预览，无内容时给出空状态。检查课程列表、搜索、管理员查看及其他接口中手工组装字段的调用。
- 正文类型采用既有 `content` 对应功能语义，继续支持 Markdown / HTML、搜索高亮、沉浸阅读、阅读完成、AI 朗读及图片；正文显示标题由模板控制。正文被省略或为空时不显示对应入口。其他文本和图片类型不自动获得正文功能。
- 预览采用管理端近似呈现，不承诺像素级或真实设备一致；不向服务器提交示例内容、不调用朗读等外部服务。真实小程序效果仍需在开发者工具及手机验收。

## 兼容、权限与发布

- 所有模板读写、绑定、复制和上传走现有管理员鉴权与租户上下文；服务端校验资源归属，平台管理员须选定目标租户。预置定义只读；不能按任意 ID 跨租户绑定。
- 旧期次和旧客户端的现有接口、旧字段含义保持兼容。旧客户端不能理解任意新模块，不能假定它能正确展示新课程：实施时先审查版本识别能力，设计可靠的最低版本准入或明确的更新提示；无法证明旧客户端可安全阅读前不得开放新模板期次。不得把任意模块强行映射到语义不同的旧字段而误导用户。
- 同步和 MySQL 热备需覆盖模板、快照和模块值，验证恢复后的可读性；数据库迁移必须非破坏、可回滚，并先验证备份完整性。若旧版本回滚无法展示新内容，运营层暂停新模板课程发布并保留新数据，不删除或覆盖。
- 管理端和服务端限制模块数、名称长度、值长度与图片类型，内容按既有安全策略渲染；正文 HTML 和链接须遵循现有过滤规则。

## 验收关键风险

历史数据兼容、复制时音视频现有例外、租户越权、模板并发编辑、快照不变性、旧客户端不可读、备份恢复、非空模块预览、正文能力回归。`question` 现有后台界面与模型长度限制不一致，应在兼容测试中核实，避免借新模板变更意外截断旧内容。
